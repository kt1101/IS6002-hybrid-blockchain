# Veritas Live Demo + Results Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single `cmd/demo` web app (sim mode on memnet, docker mode against a published `hbdb` cluster) that lets a presenter send transactions, run load, verify Merkle proofs and inject faults, plus an offline results dashboard served by the same app as its `/overview` page.

**Architecture:** Go backend split into small packages under `demo/` (`cluster`, `hub`, `load`, `verify`, `api`, `web`) behind a `cluster.Cluster` interface; the node side gains an opt-in observer (`core.ServerConfig.OnApplied` + `veritas/observe` HTTP/SSE) and opt-in published ports. UI is vanilla JS + SVG embedded with `go:embed`. The dashboard is one self-contained HTML generated by a stdlib-only Python script from `results/final/*.csv`.

**Tech Stack:** Go (module `hybrid`, go directive 1.16, builds with go1.20+), gRPC (`proto/veritas`), net/http SSE, vanilla JS (ES2017), Python 3 stdlib + pytest, Node + Playwright (pre-installed: `require('playwright')`, `chromium.launch()`; Python has no playwright) for smoke tests, bash 3.2-compatible scripts.

**Spec:** `docs/superpowers/specs/2026-11-02-live-demo-design.md` (UI mockup: canvas "Veritas Live Demo UI").

## Global Constraints

- All UI text is English. No network at runtime: no CDN, no remote fonts; fonts embedded or system stack.
- Demo HTTP server binds `127.0.0.1:8080` by default (`--listen`).
- Opt-in only: `OnApplied` nil, `--demo-events-addr` empty, `--publish-ports` off by default; E1–E6 compose output must be byte-identical to before.
- Docker ports: node i gRPC `127.0.0.1:(19900+i)`, observer `127.0.0.1:(19800+i)` (container port `7300`), TSO `127.0.0.1:19870` (container `7070`).
- Sim node config: `CommitSync`, `VersionOrdered`, `BlockSize` 100, `FlushInterval` 200ms; signatures `node<i>`, NodeID i.
- SMT leaf value = `value + "-" + version` (see `veritas/core/executor.go:applySet`).
- Timeouts: Set 10s, Get/Prove 3s, fault script 30s; load clients 1–256, duration 5–300s, key ≤128 bytes non-empty, value ≤4096 bytes.
- Colours: ink `#16181D`, ground `#F5F5F2`, accent `#1D4ED8`, ok `#15803D`, divergent `#C2410C`, down `#9AA0A6`; every state also has a text label.
- Go verification command (the whole repo does NOT build: `BlockchainDB/...`, `tso_zookeeper` have missing go.sum entries, pre-existing): `go build ./cmd/... ./veritas/... ./consensus/... ./demo/... 2>&1 | grep -v -e BlockchainDB -e tso_zookeeper` must print nothing; `go vet` and `gofmt -l` clean on touched packages.
- Commit messages end with the session's attribution trailer (given in the session).

## Review Focus

1. **Slow/blocked SSE subscriber** (browser tab in background, node observer client stuck) must never block `applyLoop` or the hub — tests: Task 3 `TestPublishNeverBlocks`, Task 6 `TestHubSlowSubscriberDropped`.
2. **Replicas at different heights** must not flash DIVERGENT — Task 6 `TestConsistencyComparesCommonHeight`.
3. **Node crashed while load is running** (sim and docker): load keeps going, errors counted, UI marks node Down — Task 5 `TestSimCrashHeal`, Task 8 `TestLoadCountsErrorsAndContinues`.
4. **Verify on a key that does not exist / on a down node** returns a clear verdict instead of 500 — Task 7 `TestVerifyMissingKey`, `TestVerifyDownNode`.
5. **Docker mode with nothing running**: `cmd/demo --mode=docker` exits 2 with a hint after 10s instead of a dead UI — Task 11 `TestDockerConnectTimeout`.
